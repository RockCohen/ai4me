# S1 答案 · 张量实验卡

> ⚠️ 先跑完全部题目再打开本文件。错题的价值在"预测为什么错"，不在正确答案本身。

| 题 | 答案 | 关键点 |
|---|---|---|
| Q1 | `torch.Size([3, 4])` | 广播把 trailing 维对齐：`(3,4)` 与 `(4,)` → `(3,4)` |
| Q2 | **RuntimeError** | `(3,4)` 与 `(3,)` 对齐时 trailing 维 4≠3。和 Q1 差在：`b` 的维度数与对齐方向 |
| Q3 | `torch.Size([3, 4])`，12 个元素 | 形状为 1 的维度可被拉伸；广播不复制数据，是"逻辑拉伸" |
| Q4 | `int64` → `float32` | `/` 是真除法，整数张量自动升为浮点。隐式 dtype 转换是经典坑 |
| Q5 | `a[0,0] == 99`；`a.t()` 同样中招 | `view/t/切片` 返回**视图**，与原张量共享同一块内存。优点是零拷贝，隐患是一改全改 |
| Q6 | `(2,4)` 与 `(2,1,4)` | `keepdim` 保留被消掉的维度——为的是之后能直接广播回去（如归一化 `x / x.sum(dim=1, keepdim=True)`） |
| Q7 | `(3,2)`、`(3,4)`、`(3,)` | `@` 是矩阵乘（内维须相等），`*` 是逐元素乘（形状须可广播）；矩阵乘一维向量时该维被吞掉 |
| Q8 | `torch.Size([])`、`0`、`float`、`torch.Size([])` | 零维张量没有形状；跨进纯 Python/打印日志时用 `.item()` 取出原生 float |
| Q9 | a、b 都是 `[2,2,2]`；`True` | `add_` 的下划线 = 原地修改，且返回的就是 `a` 本身（同一个对象）。原地操作省内存，但会悄悄影响所有引用者 |
| Q10 | `tensor([7., 1., 1.])`，t 被改了 | torch ↔ numpy 零拷贝共享（仅 CPU 张量）。改一边另一边跟着变 |
| Q11 | `mps:0` → `cpu`；x 仍在 MPS；`is_leaf=True` | 设备迁移是显式的；`x` 和 `y` 是两份独立数据 |

### 自测收尾参考

1. 广播从**最后一个维度起向前**对齐，两边维度数可以不同，缺的当 1，为 1 的可拉伸。
2. 视图零拷贝是性能优点，隐患是**共享内存被误改**——调试时"我没动它啊"类 bug 一半源于此。
3. `a.add_(1)` 原地：所有引用 a 的变量全部可见；`a = a + 1` 新建对象：旧引用看不到变化。
